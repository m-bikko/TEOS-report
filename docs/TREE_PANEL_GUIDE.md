# TreePanel — левая колонка конструктора дерева

Файл: `src/app/support-chat-builder/TreePanel.tsx`
Подключение: `src/app/support-chat-builder/page.tsx`
Модель и хелперы: `src/app/_support-shared/chatTree.ts`

Панель показывает дерево частых вопросов техподдержки как редактируемый черновик:
иерархия, перетаскивание, состояние перевода и список замечаний валидации.
Публикацией, формой узла и превью занимаются соседние компоненты — эта панель
только про структуру.

---

## 1. Контракт

Компонент **полностью управляемый**: своего состояния у него ровно два поля —
что сейчас тащат мышью и куда целятся. Всё остальное приходит сверху.

```ts
interface Props {
    nodes: SupportChatNode[];              // плоский массив, зеркало таблицы support_chat_node
    selectedId: string | null;             // выделенная строка
    expanded: Set<string>;                 // id развёрнутых узлов
    issues: ValidationIssue[];             // результат validateTree(nodes)
    onSelect: (id: string) => void;
    onToggleExpand: (id: string) => void;
    onMove: (nodeId: string, newParentId: string | null, newIndex: number) => void;
    onAddChild: (parentId: string | null) => void;   // null — раздел верхнего уровня
    onToggleActive: (id: string) => void;
    onNudge: (id: string, direction: -1 | 1) => void; // сдвиг среди соседей
}
```

Дерево хранится **плоским массивом**, а не вложенными объектами: так оно один в один
ложится на строки БД (`id`, `parent_id`, `sort_order`), и патч на бэкенд считается
без обратного преобразования. Вложенность собирается на лету функцией
`flattenVisible(nodes, expanded)` — она же отдаёт `depth` для отступа.

Родитель обязан держать:

```ts
const [nodes, setNodes] = useState<SupportChatNode[]>(CHAT_TREE);
const [selectedId, setSelectedId] = useState<string | null>(nodes[0]?.id ?? null);
const [expanded, setExpanded] = useState<Set<string>>(new Set(/* id корней */));
const issues = useMemo(() => validateTree(nodes), [nodes]);
```

## 2. Что означает каждый элемент строки

Слева направо, как на скриншоте:

| Элемент | Значение |
|---|---|
| `⠿` GripVertical | Ручка перетаскивания. Тащится вся строка, иконка — подсказка |
| `˅` / `›` | Свернуть/развернуть. Показывается только если есть дети |
| Синяя иконка диалогов | `nodeType: "MENU"` — узел открывает следующий уровень |
| Зелёная иконка сообщения | `nodeType: "ANSWER"` — узел выдаёт готовый текст (автоответ) |
| Серая иконка рядом | `node.icon` — иконка раздела в мобильном приложении. Реестр: `_support-shared/icons.tsx`, SVG-файлы: `public/icons/nodes/` |
| Заголовок | `titleRu`. Пустой — «Без заголовка» |
| Зачёркнутый серый заголовок | `isActive: false` — узел скрыт от пользователя, но остаётся в базе |
| Жёлтый бейдж `KZ` | Нет казахского перевода. Пользователю покажется русский текст |
| Синий бейдж `оператор` | `actionType: "ESCALATE"` — отсюда обращение уходит живому оператору |
| Красный кружок `!` | На узле есть ошибка валидации |

Цвет типа узла — не украшение: синий и зелёный это ровно те же цвета, что различают
пункт меню и автоответ в превью мобильного приложения, поэтому взгляд переносится
между колонками без пересчёта.

Отступ уровня — `8 + depth * 14` пикселей. Глубина не ограничена ни моделью,
ни панелью; практический предел ставит ширина колонки.

### Действия при наведении

Появляются справа, каждая — с `title` и `aria-label`:

- `↑` / `↓` — сдвинуть среди соседей (`onNudge`). Это доступная альтернатива
  перетаскиванию: клавиатурой и с тачпада им пользоваться надёжнее.
- `↳` — добавить вложенный пункт (`onAddChild(node.id)`).
- глаз — скрыть/показать (`onToggleActive`).

Кнопка `+ Раздел` в шапке — то же самое для корневого уровня: `onAddChild(null)`.

### Счётчик в шапке

`30 узлов · 5 без перевода` — второе число считается прямо в панели через
`isTranslated(node)` и подсвечивается только когда больше нуля.

## 3. Перетаскивание

Сделано на **нативном HTML5 drag-and-drop**, без библиотеки. Строка получает
`draggable`, состояние живёт в двух `useState`: `dragId` и `dropTarget`.

Строка делится на три зоны по вертикали — их считает `zoneFromEvent` из
`getBoundingClientRect()`:

```
┌──────────────────────────┐
│ верхние 25%   → before   │  вставить выше, тем же уровнем
├──────────────────────────┤
│ середина 50%  → inside   │  сделать вложенным в эту строку
├──────────────────────────┤
│ нижние 25%    → after    │  вставить ниже, тем же уровнем
└──────────────────────────┘
```

Обратная связь: `before`/`after` — синяя линия по краю строки, `inside` — синяя
рамка вокруг всей строки. Перетаскиваемая строка гаснет до 40% прозрачности.
Сброс в пустую область под деревом переносит узел в корень, в конец.

Каждое событие `dragover` и `drop` останавливает всплытие — иначе вложенная строка
и её родитель поборются за один и тот же сброс.

**Известная тонкость при автотестах.** Симулировать `dragstart` и `drop` в одном
вызове JS нельзя: React не успеет перерисоваться между ними, и обработчик сброса
увидит `dragId === null`. Разносите на два отдельных шага.

## 4. Связь с бэкендом (BE-04)

`onMove` — единственное место, где меняется структура. Родитель обязан прогнать
его через `reorder()`, а не двигать элементы массива руками:

```ts
const moveNode = (nodeId: string, newParentId: string | null, newIndex: number): void => {
    const patches = reorder(nodes, nodeId, newParentId, newIndex);
    if (patches.length === 0) return;   // перенос в себя или в собственного потомка

    const moved = applyPatches(nodes, patches, EDITOR_NAME);
    // Узел, получивший вложенность, перестаёт быть ответом.
    setNodes(
        newParentId
            ? moved.map((n) => (n.id === newParentId ? { ...n, nodeType: "MENU" as const } : n))
            : moved,
    );
    setLastPatch(patches);              // это и уходит в BE-04
    if (newParentId) setExpanded((prev) => new Set(prev).add(newParentId));
};
```

Два довеска к переносу обязательны, иначе пользователь упрётся в состояние, которого
не ожидал. Первый: узел, в который что-то вложили, автоматически становится `MENU` —
иначе сразу после сброса валидация выдаст ошибку «ответ с вложенными пунктами».
Второй: этот узел разворачивается, иначе перенесённая строка визуально исчезает.

`onNudge` — не отдельная ветка логики, а тот же `moveNode` с соседним индексом.

`reorder()` возвращает `ReorderPatch[]` — перенумерованные `parent_id`/`sort_order`
**обоих** затронутых уровней сразу, и исходного, и целевого. Отправлять их нужно
одним массовым запросом: если применять по одному, дерево между запросами окажется
в состоянии с дырами и дублями в `sort_order`.

Защита от переноса узла внутрь самого себя уже внутри `reorder()` — панель
про это не знает и знать не должна.

## 5. Панель замечаний

Нижний блок — `validateTree(nodes)`, те же правила, что на бэкенде.

**Ошибки** (красный кружок) блокируют публикацию:

- ответ с вложенными пунктами — `ANSWER` не может быть родителем;
- меню без единого активного ребёнка — пользователь упрётся в пустой экран;
- пустой `titleRu`;
- `ANSWER` с пустым `bodyRu`;
- цикл: узел оказался собственным предком.

**Предупреждения** (жёлтый треугольник) публикацию не блокируют:

- нет казахского перевода — переводы законно отстают от русского текста;
- из корневой ветки не достижим ни один `ESCALATE` — ветка тупиковая, позвать
  оператора из неё нельзя.

Клик по замечанию выделяет проблемный узел (`onSelect(issue.nodeId)`) — это
основной способ навигации по ошибкам в большом дереве.

Когда замечаний нет, блок превращается в зелёную плашку «Замечаний нет — дерево
можно публиковать». Пустое место под деревом вместо явного «всё хорошо» читается
как «проверка не запускалась».

## 6. Грабли

**Побочные эффекты — вне апдейтера состояния.** Не вызывайте `setSelectedId`
внутри `setNodes(prev => ...)`: в Strict Mode апдейтер выполняется дважды.
Считайте новый id из текущего `nodes` до вызова `setNodes`.

**`flattenVisible` возвращает и неактивные узлы.** Так и задумано: в конструкторе
скрытые пункты должны быть видны, иначе их не вернуть. Мобильное приложение читает
дерево через `childrenOf(nodes, parentId)` без `includeInactive` и их не получает.

**`makeNode` использует `Math.random()` и `Date.now()`.** В проекте они запрещены
в рендере из-за гидрации, но здесь вызов происходит в обработчике клика — то есть
только на клиенте и только после гидрации. Не переносите его в тело компонента.

**Панель не хранит дерево.** Любое изменение проходит через родителя. Это
осознанно: черновик, опубликованная версия и diff между ними живут в одном месте,
и панель не может рассинхронизироваться с тем, что уйдёт на бэкенд.

## 7. Если переносить в боевой ERP

1. Заменить `CHAT_TREE` на загрузку по BE-01, форма ответа совпадает.
2. `onMove` → `reorder()` → PATCH массивом на BE-04.
3. `validateTree` продублировать на сервере. Клиентская проверка — для удобства,
   решение о публикации принимает бэкенд.
4. Иконки: в БД лежит имя в PascalCase (`CalendarClock`), файл — kebab-case
   (`calendar-clock.svg`). Перевод закреплён в `nodeIconPath()`,
   таблица соответствий — `public/icons/README.md`.
5. Ширина колонки в стенде 296px. Ниже ~260px заголовки обрезаются до бесполезного;
   если места меньше, переносите бейджи на вторую строку.
