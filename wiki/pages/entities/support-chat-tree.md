# Дерево частых вопросов

Справочник тем, по которому пользователь идёт в начале обращения в техподдержку. Каждый
пункт либо раскрывает следующий уровень, либо выдаёт готовый ответ. Глубина не ограничена.

Модель — зеркало таблиц бэкенда из [[be-01-06-chat-tree-contract]]. Редактируется
в [[support-chat-builder]], потребляется в [[support-chat-flow]].

## Ключевое решение: плоский массив

Узлы хранятся плоским списком, как строки таблицы `support_chat_node`, а вложенность
строится на лету. Сделано намеренно: стенд должен показывать бэкенду ровно то, что лежит
в БД, и делать очевидным, почему перенос узла — это один массовый запрос, а не серия
точечных апдейтов.

## Типы узлов

- `MENU` — раскрывает следующий уровень. Обязан иметь хотя бы одного активного потомка.
- `ANSWER` — лист с текстом автоответа. Потомков иметь не может.

Тип — явное поле, а не вычисляемое из наличия детей. Но конструктор поддерживает
инвариант сам: узел, в который перетащили потомка, автоматически становится `MENU`.

## Действие под ответом

Поле `actionType` плюс `actionPayload` определяют, что рисуется под текстом:

| Значение | Что даёт |
|---|---|
| `NONE` | ничего, ветка кончается текстом |
| `ESCALATE` | кнопка передачи обращения живому оператору |
| `OPEN_LINK` | кнопка-ссылка на внешнюю инструкцию |
| `OPEN_SCREEN` | диплинк внутрь мобильного приложения |
| `CALL_CENTER` | звонок; пустой номер берётся из настроек |

Набор не был задан постановкой — предложен на стенде, по одному значению на реальный
элемент интерфейса. `ESCALATE` критичен: без него ветка никуда не ведёт, поэтому его
отсутствие ловит валидация.

## Валидация

Шесть правил, одинаковых для CRUD и импорта. Пять блокируют публикацию: `ANSWER`
с потомками, цикл, `MENU` без активных потомков, пустой заголовок, пустой текст ответа.
Шестое — предупреждение: в ветке нет достижимого `ESCALATE`.

## Локализация

В контракте бэкенда есть `title_kz` / `body_kz`, но на стенде их нет: демо одноязычное
по решению заказчика, переключатель языков в проекте живёт в другом месте.
